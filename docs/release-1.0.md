## Подготовка (сервис работает)

1. Релизный клон: `git clone "$(git -C "$LIVE" remote get-url origin)" "$REL" && cd "$REL" && git checkout <релиз>` — `ls "$REL/deploy/.env"` сообщает «нет файла».
2. `cd "$REL" && make release-prepare LIVE="$LIVE" PROFILES=embeddings,rerank GPU_MEM_UTIL=0.81` — собраны образы, в конце напечатаны команды окна и отката; вывод сохранить, записать `<прежний коммит>`. Ошибка сборки — стоп: повторить после восстановления доступа к PyPI и npm.
3. `cd "$REL" && make release-rehearse LIVE="$LIVE"` — строка «репетиция миграций прошла за N с» (применяется 0011 на копии рабочей базы).
4. Файлы клиента CoGIS (jQuery, Knockout, Leaflet; нужны предпросмотру и подсказкам редактора; собственность заказчика, в git не попадают). Каталога с ними на сервере CoGIS не закреплено — найти на сервере CoGIS:
    ```bash
    find /usr/elitegis -type f \( -iname 'jquery*.js' -o -iname 'knockout*.js' -o -iname 'leaflet*.js' -o -iname 'leaflet*.css' \) -not -name '*.map'
    ```
    Взять сами файлы библиотек (не архивы и не общий пакет клиента; меньше 4 МиБ, UTF-8), скопировать без преобразования (`scp`) на ВМ в `$CLIENT_SRC` и положить под постоянными именами:
    ```bash
    install -d -m 755 "$SDK/client"
    cp "$CLIENT_SRC/<файл jQuery>" "$SDK/client/jquery.js"
    cp "$CLIENT_SRC/<файл Knockout>" "$SDK/client/knockout.js"
    cp "$CLIENT_SRC/<файл Leaflet>" "$SDK/client/leaflet.js"
    cp "$CLIENT_SRC/<файл стилей Leaflet>" "$SDK/client/leaflet.css"
    ```
    Проверка: `ls -1 "$SDK/client"` — четыре файла (или меньше, если какой-то библиотеки нет на сервере CoGIS): `jquery.js`, `knockout.js`, `leaflet.js`, `leaflet.css`. Каждая библиотека необязательна, но код, который ею пользуется, в предпросмотре не заработает.
5. Подсети Docker не пересекаются с сетью баз. Базы стоят в той же частной сети VPN, что и ВМ, и указываются по IP; Docker выбирает подсети своих сетей из пулов `172.17.0.0/16`–`172.31.0.0/16` и `192.168.0.0/16`. Пересечение — база недоступна, портал отвечает `host_forbidden`.
    ```bash
    docker network ls -q | xargs docker network inspect -f '{{.Name}} {{range .IPAM.Config}}{{.Subnet}} {{end}}'
    ```
    Ожидание: ни одна подсеть в списке не пересекается с подсетью VPN заказчика и не содержит адрес базы. Пересекается — стоп; исправление в окне (простой несколько минут): в `/etc/docker/daemon.json` задать пул **вне подсетей VPN заказчика**, например `{"default-address-pools":[{"base":"10.222.0.0/16","size":24}]}` (при существующем файле — добавить ключ), затем `cd "$LIVE" && make down && systemctl restart docker && make up`, повторить команду проверки. Пересечение с `docker0` (`172.17.0.0/16`) пул не меняет — для него в `daemon.json` нужен `"bip"` вне VPN.
6. Доступ к базе. Правило межсетевого экрана с ВМ к `<адрес базы>:<порт>` — заявка DevOps (`devops-request.md` §1.5); учётная запись «только чтение» — у администратора базы: передать ему раздел `runbook.md` §3.12 «Памятка администратору базы»; для режима «С проверкой сертификата сервера» корневой сертификат заказчика (один файл PEM, в нём может быть несколько сертификатов) — в `$LIVE/deploy/portal/customer-root-ca.pem`. Проверка с ВМ: `timeout 5 bash -c 'exec 3<>/dev/tcp/<адрес базы>/<порт>' && echo открыт` — «открыт». Нет — стоп: правило не выполнено (подключения не включать, остальной релиз можно раскатывать).
