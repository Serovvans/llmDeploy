# Заявка DevOps: сетевые настройки для LLM-сервиса

Контекст: на ВМ с RTX PRO 5000 (72 ГБ) разворачивается self-hosted LLM с
OpenAI-совместимым API. Единственная публичная точка входа — HTTPS на порту 443.
Полное описание — `docs/design.md`.

Работы разбиты на два этапа (`docs/design.md` §3.7), чтобы не ждать друг друга.
Этап 1 — развёртывание и тестирование модели на ВМ — требует только саму ВМ, доступ по
SSH и исходящий трафик (§1.4); он идёт параллельно с этой заявкой. DNS-имя (§1.1),
сертификат (§1.2) и входящий 443 (§1.3) нужны на этапе 2, когда сервис открывается
клиентам.

## 1. Что нужно настроить

### 1.1 DNS
- Внутренняя A-запись для ВМ, предлагаемое имя: `llm.<корп.домен>` (согласовать).
- Имя должно резолвиться у VPN-клиентов и на серверах приложений.

### 1.2 Сертификат
Желательно, но не блокирует установку. Если выпустить сертификат нельзя или долго,
сервис ставится с собственным CA Caddy (`TLS_MODE=internal`, `docs/design.md` §3.4). Тогда
его корневой сертификат раздаётся серверам приложений и UI, а на корпоративный
сертификат можно перейти позже без изменений у клиентов.

- Сертификат корпоративного CA на имя `llm.<корп.домен>` (SAN = DNS-имя).
- Формат: PEM (cert chain + private key), передать администратору ВМ.
- Срок действия и процедура перевыпуска — сообщить, чтобы заложить в runbook.
- Корневой сертификат CA должен быть в доверенных у рабочих станций и серверов
  приложений (обычно уже есть через GPO).

### 1.3 Входящий трафик на ВМ (файрвол / security group)

| Порт | Протокол | Откуда | Назначение |
|---|---|---|---|
| 443 | TCP | VPN-подсети сотрудников, серверы приложений и UI | API LLM (обязательно) |
| 22 | TCP | Подсеть администраторов | Администрирование, SSH-туннель к админ-UI |

Всё остальное входящее — запретить. Порты 3000 (Grafana), 8000/8001 (vLLM), 8080
(gateway), 9090 (Prometheus) на внешний интерфейс не публикуются — только
localhost/docker-сети; Grafana и админ-UI — через SSH-туннель.

### 1.4 Исходящий трафик с ВМ

| Назначение | Порт | Зачем |
|---|---|---|
| `huggingface.co`, `cdn-lfs.huggingface.co`, `cdn-lfs-us-1.huggingface.co`, `*.hf.co` (в т. ч. `cas-bridge.xethub.hf.co`) | 443 | Загрузка моделей (при установке и смене модели) |
| `registry-1.docker.io`, `auth.docker.io`, `production.cloudflare.docker.com` | 443 | Docker-образы |
| `ghcr.io`, `pkg-containers.githubusercontent.com` | 443 | Docker-образы |
| `nvcr.io` | 443 | dcgm-exporter (мониторинг GPU) |
| `download.docker.com`, `nvidia.github.io`, `astral.sh`, `github.com`, репозитории Ubuntu | 443 | Установка Docker, NVIDIA Container Toolkit, uv, обновления |
| NTP-сервер | 123/UDP | Синхронизация времени (TLS) |

После установки исходящий доступ к Hugging Face можно закрыть — сервис работает
офлайн, пока не понадобится сменить модель.

## 2. Вопросы к DevOps

1. Гипервизор и параметры ВМ: vCPU, RAM, размер диска? Требуется ≥ 8 vCPU,
   ≥ 64 ГБ RAM, ≥ 300 ГБ SSD.
2. Какие VPN-подсети и адреса серверов приложений разрешить на 443?
3. Можно ли выпустить сертификат корпоративного CA, кто и по какой процедуре? Срок
   действия? Если нет — подтвердить использование собственного CA Caddy (§1.2).
4. Нужен ли корпоративный прокси для исходящего HTTPS (если да — адрес и исключения)?
5. Есть ли центральный Prometheus/Grafana/лог-сборщик, куда отдавать метрики и
   логи, или разворачиваем локально?
6. Резервное копирование ВМ: включить в общий регламент? Критичные данные — volume
   `bifrost-data` (API-ключи и лимиты, несколько МБ) и, при собственном CA Caddy,
   `caddy-data` (корень CA с ключом, хранить как секрет).
7. Кто администрирует ВМ после передачи (доступ по SSH, sudo)?
8. Требования к именованию/тегированию ВМ и к автозапуску сервисов после
   перезагрузки (используем systemd + docker compose).

## 3. Требования к ОС на ВМ

От DevOps нужна чистая Ubuntu с доступом по SSH и sudo. Драйвер, Docker и Toolkit ставит
`scripts/install_host.sh`, для этого нужен исходящий доступ к `download.docker.com`,
`nvidia.github.io`, `astral.sh`/`github.com` (uv) и репозиториям Ubuntu. Если ставить
пакеты из интернета нельзя, требования ниже выполняет администратор ВМ.

- Ubuntu 24.04 LTS (допустимо 22.04 и 26.04).
- Драйвер NVIDIA ветки ≥ 580, open kernel modules: `nvidia-driver-580-server-open` или
  новее (`nvidia-driver-595-open`).
  Для Blackwell проприетарный модуль не поддерживается.
- Docker Engine ≥ 27, NVIDIA Container Toolkit, автозапуск docker.
- Проверка: `nvidia-smi` показывает RTX PRO 5000 72 ГБ;
  `docker run --rm --gpus all nvidia/cuda:13.0.1-base-ubuntu24.04 nvidia-smi` работает.
